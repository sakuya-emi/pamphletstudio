# 2026-11-27 改善実装と検証

添付の改善実装プロンプト、v10〜v12改善点まとめ、Excel template v2を確認して実施。SPEC-Jの制作フローを維持し、公開サイトへのデプロイは行っていません。

## 第1優先：保存と孤立データ

- 再現できた原因：`writeSource`で開催回数を空欄にすると `undefined` を保存していた一方、読み込みの `validateProject` は有限の数値を要求していました。IndexedDBは明示的なundefinedを保持するため、保存成功後に一覧から外れる経路がありました。監査時のブラウザそのものの孤立データは取得していないため、監査事例と完全に同じ破損内容だったとまでは断定しません。
- 空欄の開催回数を0（未設定）として扱い、過去に保存されたundefined/null/空文字の開催回数も読み込み時に回復します。日付・時間・大学名の空文字は維持します。
- ブラウザ自動保存・.pamph保存の前に、構造検証、JSON化後の再読込検証、素材ID・データ形式・寸法の検証を行います。拒否した保存は既存データを置き換えません。
- 読めないデータがあっても正常データは一覧に残します。読めない項目は保存キーに対応した管理ID・名前・理由を表示し、対象を確認するダイアログからその項目だけを削除できます。勝手な削除や正常データの一括削除は行いません。
- 実際の添付Excelの53変更行（認識60行のうち変更不要7行を除外）を反映し、基本情報4項目を空欄化、実PDF生成、保存→再読込→.pamph再読込→選択削除までを回帰テストにしました。

## 第2優先：ポスター要否

- 学生企画・模擬店・ステージ企画・学生ステージ企画・外部／特別企画のExcel列「ポスター要否」を読み取ります。「要」「不要」のみを受け付け、空欄と旧Excelで列がない場合は「要」です。再取り込み時にもこの規則を適用します。
- `posterRequired?: boolean` の任意属性を追加し、既存形式5のプロジェクトで属性がない場合は「要」とします。既存データのスキーマ更新は要求しません。
- 不要なポスターは画像フロー・未登録集計から除外します。非掲載とキッチンカーの既存ルールは維持します。不要でも企画名・開催時刻等はテキストの誌面に残します。要の未登録画像には登録先と企画名付きのプレースホルダー・警告を出します。
- 外部／特別企画は既存設計の文章ページとして保持し、そのページに任意のポスター属性を持たせました。「不要」は文章中心のまま、「要」は画像登録対象です。内容やIDを別カテゴリへ強制移行しません。
- ステップ2の企画表に要否チェックを追加し、ステップ3の企画タブにも選択欄を追加しました。外部／特別企画はステップ2「共通情報・文章」の要否行とステップ3の企画タブで変更できます。
- 新雛形を `public/templates/Pamphlet-Studio-Excel-template-v2.xlsx` に同梱し、Excel取り込み画面からダウンロードできます。
- 添付雛形の開会式・閉会式が不要として保存され、画像フロー・未登録警告から除外されることを自動テストとChromiumで確認しました。ブラウザの通常取り込みでは認識60件、既定の登録予定51件（要確認行は明示選択まで除外）。画像の概要は表紙1・ポスター25・店舗2・広告3＝31件でした。
