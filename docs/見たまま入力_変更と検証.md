# 見たまま入力できる制作モード：変更と検証

更新日：2026-11-07

## 今回の変更

制作プレビューの文字・企画表・ポスター・広告・章タブ・ページ番号から、元の登録情報を編集するパネルを開く。PCは右側、幅760px以下では下部パネルで表示する。スマートフォンではプレビュー幅を画面内へ収め、編集中も上部にプレビューを残す。デザイナーの作図画面は変更しない。

空の企画表には「企画を追加」、ポスター未登録部分には「ポスターを登録」、空き広告枠には「広告を登録」を表示する。企画・広告・スタッフ・キッチンカーの追加は、選択後すぐ入力欄を表示する。ポスターは既存企画への登録と新しい企画の作成を選べる。ステージは既存企画の一覧から編集、または追加できる。

企画は企画名・団体名・開催場所、ステージは名称・開始終了時刻・ポスター、キッチンカーは会社名・複数メニュー・画像、広告は企業名・規格・素材、スタッフは氏名を編集する。素材の選択・ドラッグ＆ドロップ・差し替えを行える。企業名はEnterまたは入力欄から離れた時点で確定し、入力途中の文字列ごとに企業を増やさない。

表紙の開催情報・画像・大学ロゴにも元データへの編集先を付けた。開催回数と学園祭名の合成表示、場所の合成表示は、構造化された元の項目を編集する。ページ番号は開始番号を変更する。自由な文字移動や装飾変更は制作モードへ追加しない。

編集はProject内の既存データを更新し、自動組版を再実行する。ページ数や順序ではなく情報の種類とIDで追跡する。再配置後は対象を含むページへ追従する。Undoで対象自体がなくなった場合はパネルを閉じる。

「表形式で編集」から対応するシート・行へ移動する。作業ページの各行の「誌面へ」で対応するページへ戻れる。未配置の場合はその旨を表示し、重複登録しない。

入力ガイドはSVG上の編集専用の層として表示し、PDFの描画ノードへ追加しない。既存の未登録広告・ロゴ・空欄の案内にもeditorOnly属性を付け、PDFとサムネイルから除外した。PDFの文字・図形・埋め込み素材の描画方法は維持する。

広告の規格変更時は旧枠への指定を外し、必要な規格の広告ページを用意する。規定寸法へ無理に縮小しない。ポスターの自動改ページ・縦横比・キャプションなしの既存仕様を維持する。

## 互換性・範囲

.pamphの構造とスキーマバージョンは変更しない。既存のID・素材・テンプレート参照を保持する。editorOnlyは自動生成された描画ノードの属性で、プロジェクトの登録情報を削除しない。

今回、新しいページ番号の表示形式は追加していない。開始番号は直接編集パネル、その他の既存デザイン設定は従来の画面で扱う。箇条書きは本文の改行で追加・削除・並べ替える。専用の項目ドラッグ操作は今回追加していない。

ポスターを持つ企画が0件の場合、自動組版は引き続き空のポスター専用ページを生成しない。登録は企画一覧のポスター登録ガイドから行う。公開先とブラウザが変わるとブラウザ内の保存領域は別になるため、移行時には.pamphを書き出して開く。

## サブフォルダーへの公開

ロリポップの `web/domain/pamphlet-studio` に配置する構成。公開ビルドは `npm run build -- --base=/pamphlet-studio/`。画面側とPDFワーカー側のフォント取得はViteのBASE_URLを使用する。通常のローカル開発では従来どおりルートから起動できる。

転送対象はdist内のindex.html・assets・fonts（ライセンスを含む）のみ。登録された制作データ・.pamph・開発文書・差分ZIPは公開サーバーへ送らない。
