# 初見最短フロー：SPEC-J と v10 監査への対応

2026-11-26（JST）。GitHub の `3b8b520` を基準に、添付された v10 監査結果と SPEC-J を実装した記録です。公開デモサイトのデプロイはこの変更に含みません。

| 項目 | 実装 |
| --- | --- |
| J1：Excel ドロップ | ステップ2の先頭に大きなドロップ領域。クリック・Enter・Spaceでも選択可能。同じ読み込み処理で既存のプレビューへ進む。不正な拡張子・複数ファイルは案内を表示。 |
| 要確認の扱い | 既存文章との相違・重複候補の意味、変更前後の確認、更新／新規追加／登録しないの選び方、未選択の行は取り込まれないことを説明。既存の判断ロジックは維持。 |
| J2：画像登録 | 開始前に表紙・ポスター・店舗・広告の内訳と総数を表示。表紙を先頭にし、全件一括スキップと種類ごとのスキップを追加。一括スキップは概要画面から1クリックで誌面へ進む。 |
| 画像件数 | 表画面と画像フローで同じ集計処理を使用。非掲載の企画・広告は除外し、参照先の実素材がない場合も未登録として数える。表紙未登録の出力警告は維持。 |
| J3：ページ数 | 出力総ページ数を主表示とし、誌面と自動白紙を内訳表示。増減時にExcel取り込み／編集による再計算と増減数を通知。ページ送りはPDFの位置を主表示、印刷される誌面番号は補足へ移動。 |
| J4：基本情報 | 共通情報タブの6行と、直接編集・編集パネルの基本情報入力欄を除去。Excelからの6項目の反映は維持。空の行や基本情報シートがない場合は既存値を維持し、未設定でのPDF出力を妨げない。 |
| J5：デザイン | 全7画面の順序を冒頭で表示。配色の初期見本と「標準のみ」を表示。進む導線は1つにし、最後にExcelへ進む。デザイン見本のラベルからPDFの物理ページ番号を除去。 |
| ステップ・説明 | ステップ2を「Excelを読み込む」に統一。表画面の次へボタン、警告件数ラベル、編集パネル各タブの役割、入力不足が数える項目を明記。 |
| 確認と完了 | 校正チェックは任意の記録と明記。警告・未確認だけなら校正PDFを出力可能。画面移動や任意チェックだけでは生成済みPDFを古い扱いにしない。出力内容の編集で再出力が必要になる。エラーは従来どおり出力を阻止。 |
| プロジェクト一覧 | 重複しない初期名を連番で生成。同名でも年度・出力ページ数・PDF状態・企画数・管理IDで区別できる。単一の.pamph選択とフォルダ内の.pamph一括読込を区別する文言に変更。 |

## 検証

- 既存202件と最短フローの追加回帰テスト。基本情報6項目の反映、7つの基本情報ソース（複合表示を含む）の編集UI除去、未設定の基本情報と未登録表紙での実PDF生成、非掲載・欠損素材の画像件数、命名、見本のラベル、PDF状態を検証。
- `npm run build`：TypeScript型チェックとVite本番ビルド。既存の大きなチャンク警告あり。
- Chromium実操作：新規作成→全7画面→キー操作のファイル選択→Excelの実ドロップ→取り込みプレビュー→画像概要（表紙1・ポスター28・店舗2・広告1、合計32件）→先頭の表紙にPNG登録→一括スキップ→校正チェック未確認のままPDFをダウンロード。
- 同じブラウザでステップ2へ戻ってPDF生成済み状態が維持され、共通情報から基本情報の入力欄が消えていることを確認。異なる大学名を持つExcelを再取り込みし、要確認行の明示更新→画像概要から1クリックでスキップ→出力後に変更あり、まで確認。ブラウザの未処理エラー0件。
- ブラウザ用のExcelは合成データであり、監査時の元Excelではありません。監査の28ページと同一の内容を復元した検証ではありません。26誌面＋自動白紙2＝出力28ページの表示・白紙生成は自動テストでも検証しています。

印刷用CMYK・PDF/X等やデザイナー自体の機能変更、既存データの移行は対象外です。Mac内の既存プロジェクトや公開デモの保存データは変更していません。
