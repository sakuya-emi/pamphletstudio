# 軽量化：実装と計測

更新日：2026-11-07

制作画面・デザイナーの操作、組版仕様、素材とフォントの品質、.pamph保存形式を維持する。公開サーバーには今回の変更を転送していない。

## 変更

- デザイナーモード、PDF.js、SVG変換用のjsPDF・svg2pdfを必要になった時点で読み込む。通常の画像登録にはこれらを読み込まない。
- フォント幅の測定をPDF描画モジュールから分離。フォントに適用する文字処理と幅の計算式は同じ。フォント・文字列ごとの幅を再利用し、キャッシュの件数を制限する。
- アンケートと裏表紙のQRパスは、URLと配置が同じ場合に再利用する。出力の座標・ベクター品質を維持する。
- 変更前のプロジェクトは既に編集用の複製から分離されているため、取り消し履歴へ入れる際の二度目の全体コピーを省く。PDFワーカーからPDF本体を返す際も転送可能なバッファを使い、コピーを省く。
- 同じTrueTypeフォントを可逆圧縮して配信する。画面描画と幅測定に同じ取得データを使う。圧縮に対応しない環境では元のTTFを使う。フォントの削減・置換は行わない。

## 計測

ビルド成果物の圧縮前のJSサイズ：起動時に必要なJS（エントリとフォント幅測定）は2,622,011バイトから1,302,280バイト。エントリ単体は538,171バイト。各機能の遅延読み込み分は起動時の集計から除外。

フォント2書体の素材ファイルは43,346,260バイトから23,432,661バイト。展開結果が元のTTFとバイト単位で一致することを確認。転送量の削減は圧縮ファイルを配信できる場合の値で、ブラウザのキャッシュやサーバー側圧縮によって実際の転送量は変わる。

同じ50企画を25回組版するローカル比較：幅キャッシュなし約5,547ms、キャッシュあり約184ms。フォントの初期化後、最初の組版で結果が一致することを比較した上で測定した。操作全体や初回起動の所要時間を表す値ではない。

## 確認と適用

- 自動テスト160件成功。本番ビルド成功。
- ブラウザでフォント読み込み、新規作成、遅延読み込み後のデザイナー、SVG・PDF素材の登録、A5 PDFのダウンロードを確認。
- 差分適用後は従来どおり `npm run dev` または `npm run build -- --base=/pamphlet-studio/` を実行する。各事前処理が `public/fonts/*.ttf.gz` を生成するため、差分ZIPには生成済みフォントを含めない。再公開時は `dist` のフォントも含めて配置する。
